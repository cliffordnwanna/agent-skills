# Interview pack

Build it on request, using the angle already chosen for the application (in fast mode the skill picks the strongest angle itself; in careful mode, the one the user approved). Everything comes from the portfolio and the user (truth rule).

## About fifteen likely questions

Mix, weighted to the role:
- Background and motivation (2)
- Role-specific technical or domain questions drawn from the must-haves (5 to 6)
- Behavioural questions (4 to 5): conflict, failure, leadership, prioritising, working remotely and across time zones
- Questions about the user's gaps, answered honestly (2)
- Questions about the company and the role (1 to 2)

## Answers in STAR form

For each question, write **Situation, Task, Action, Result** from a real project or role in the portfolio, in a conversational voice, highlighting the user's own contribution. If the result has no known figure, write the qualitative outcome and add `[add your real figure if you have one]`. Never invent a figure, a team size or a date.

Name the portfolio item each answer draws on, so the user can check the source.

## Employer-confidential work

Use the capability-level description from `cv-rules.md`. If an answer would need confidential detail, tell the user what to leave out.

## Gaps

For each must-have marked missing or partial, give an honest answer: what the user has done that is closest, what they are learning, and how they would close the gap. Do not pretend.

## Questions to ask them (three)

Sharp, specific questions that show research from the company brief (team structure, how success is measured in the first months, how remote work and time zones actually run, hiring process and timeline). Avoid questions answered on their website.

## Output

A document the user can read the night before: the questions with answers, the three questions to ask, and a five-line cheat sheet of the user's strongest proof points for this role.
