# Gig mode (quick contracts and hourly work)

Use when the posting is a short contract, task or project, or hourly work (for example freelance, AI training or labelling, evaluation, support shifts, content or social media work). The user wants speed and income, often in a foreign currency.

## Output (lean, in this order)
1. **Serious warning first** only if the legitimacy risk is high (see the gig-scam signs in `legitimacy-checklist.md`). Other warnings go near the end.
2. **Pre-filled answers** to every question in the posting or application form, ready to paste.
3. **A one-page CV** tuned to the gig (skills and evidence that match the task first), as a file.
4. **A short pitch**, three to five sentences, instead of a full cover letter, unless the posting asks for one.
5. **Rate suggestion:** where a rate must be stated, give one at or above the user's target, in the posting's currency. Never state the floor.
6. **Next steps** (at most five lines) and **Improve next**.

Never bundle files into a ZIP: each document is its own download.

**High-risk postings:** the rule in `SKILL.md` (rule 7) applies here too. Show the warning first, draft no outreach or pitch message to send, and do not ask the user for personal details.

## Practical points
- Note assessment or test steps in the posting and how to prepare in a line or two.
- Convert the stated rate to the user's currency only if useful, and say the exchange rate used is approximate.
- Payment: check the posting's payment method against the user's accepted routes. Flag mismatches.
- Do not ask the user for ID, bank details or remote access to complete an application.
